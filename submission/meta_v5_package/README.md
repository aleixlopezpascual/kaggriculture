## What Step1010 does

When a hand's action is `PASS`, and that hand is already standing on a tile
where useful work is legal, the `PASS` is replaced by that work:

- unwatered crop -> `WATER`
- animal with fertiliser ready -> `COLLECT_FERTILIZER`
- animal not yet cared for -> `CARE`

It **only ever rewrites `PASS`**, so it can never displace an action the engine
chose. One hand per tile. Any exception falls through to the parent action
unchanged, matching the Step1009 convention (including writing the rewritten
action back into `_RACE_STATE`).

## Why harvesting is excluded

The obvious fourth rule -- harvest a tile with `yield_units > 0` -- **lost
0-48** (p=7e-15, mean -$856). `yield_units > 0` means "has *some* yield", not
"is at max yield"; crops keep accumulating and the engine waits deliberately.
The rule survives behind `S1010_MODE=harvest` only so the Phase 13 ablation
stays reproducible. **The shipped default is `safe`, which excludes it.**

## Validation

Paired A/B versus stock Meta V4, both seats, five independent seed batches
(672 matches over 336 distinct seeds):

| | |
| --- | --- |
| record | W85 L41 T546 |
| decided-game win rate | 67.5% |
| 95% Wilson CI | 58.9% - 75.0% (excludes 50%) |
| sign test | p = 0.00011 |
| mean margin | +$5 |
| worst step latency | 72.8 ms (stock V4: 71.9 ms) |

The mean margin is tiny by design: 81% of mirror matches end in an *exact*
tie, and this layer converts a share of those ties into wins rather than
building a larger farm. Live, Meta V4 ties 21% of its episodes.

See `docs/experiments.md`, Phase 13, for the full derivation and for the three
levers that were rejected.
